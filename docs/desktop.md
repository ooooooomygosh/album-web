# 沉入桌面 · Desktop sink

One feature replaces the old **桌面模式** (interactive window at desktop level,
covering the icons) and **动态桌面背景** (non-interactive wallpaper behind the icons).

## What happens on one click

1. The cabin window collapses to the tray / menu bar.
2. The scene is painted **behind the desktop icons** (Windows: `DesktopHost.exe attach`
   under WorkerW; macOS: a `type: 'desktop'` window). Desktop icons stay usable.
3. Interactive layers exist only where needed, everything else is click-through:
   - the pet window (hit-testing on painted pixels: click, drag, throw);
   - a pixel **mini player** in the bottom-left of the work area, at desktop level
     (below every app window). Hover reveals ▶/❚❚, sound, focus and 「浮出」.
4. If the behind-icons layer cannot be attached (another live-wallpaper app,
   Explorer variant), the app falls back to the legacy interactive desktop-level
   window with the widgets, and reports `via: 'window'` plus a `reason`.

Exit: tray / menu-bar 「浮出桌面」, double-click the tray icon, double-click the mini
player, its 「浮出」 button, or **Ctrl/⌘ + Alt + D** (global, also enters).

Performance: on battery or with the screen locked the scene drops to 10 fps (30 fps on AC).
The room cat is hidden in the wallpaper while the interactive pet is out, so it never appears twice.
Multi-monitor: the scene and mini player use the display the cabin window was on;
they refit on resolution / docking changes.

## Renderer API (for onboarding / settings)

Import from `src/desktop/desktop-sink-client.mjs`, or use `window.cabinDesktop` (installed by the cabin room):

| call | returns |
| --- | --- |
| `enterDesktopMode()` | current status; asks the shell to sink (no-op if unsupported / active) |
| `exitDesktopMode()` | current status; asks the shell to surface |
| `getDesktopModeStatus()` | `{ active, busy, supported, via, reason }` |
| `onDesktopModeChange(cb)` | unsubscribe function |

Event: `window` receives `cabin:desktop-mode` with the same status as `detail` on every change.
`supported` is false in the browser preview and on Linux; `reason` is a user-facing Chinese sentence.

Tray / menu-bar icon follows the room pet automatically (`tray-pet` shell command, internal).
Icons are generated by `npm run icons` into `desktop/assets/tray/`:
`<pet>Template.png` / `@2x` (macOS template, tinted by the menu bar) and `<pet>.ico` (16 + 32 px).

## Migration

`window.json` flags `desktopMode` (old 桌面模式) and `wallpaper` become `desktopSink`.
Shell commands `desktop-mode`, `desktop-mode-exit`, `wallpaper-start`, `wallpaper-stop`
remain as aliases of `desktop-sink`, `desktop-sink-exit`, `desktop-sink-enter`.

## Platform limits

- Windows: behind-icons needs WorkerW (Explorer). Some wallpaper apps own it; then the
  window fallback is used. Fullscreen games cover the desktop and Chromium's occlusion
  tracking usually pauses painting, but this is not guaranteed for WorkerW children.
- macOS: desktop-level windows hide under Stage Manager's desktop click-to-reveal; the
  mini player is per-Space-visible but not shown over fullscreen apps by design.
- Only the display holding the cabin window gets the scene (no per-monitor scenes yet).
