# Album Circle 产品与执行计划

## 目标

做一个跨平台 Web App，让朋友围绕一张专辑或一首歌共同填写推荐、评论和补充资料。用户可以输入歌曲名、作者或来自网易云、QQ 音乐、Spotify、Apple Music 等平台的分享链接；系统自动搜索候选曲目/专辑/封面/制作人/曲目/创作背景，并让用户确认正确版本，避免同名歌、豪华版、现场版、地区版误合并。

## 调研结论

- Rate Your Music 的价值在于可沉淀的评分、评论、列表和社区数据库，但门槛高、审核重，适合借鉴“长期档案”和“列表”。
- Album of the Year 强在聚合专业评分、用户评分和年度榜单，适合借鉴“专业评论 + 好友评论 + 时间维度”的组合。
- Musicboard 的“音乐版 Letterboxd”路径更接近本产品：写短评、评分、排行、listen later 和个人主页；用户反馈里搜索不稳定、崩溃和找不到专辑是高频痛点。
- Last.fm 证明听歌历史和推荐可以长期留存，但近年用户常抱怨社交功能弱、跨平台 scrobble 元数据不完整，尤其 album artist 和版本信息容易丢。
- Discogs / MusicBrainz 更适合作为“准确版本、厂牌、发行、制作人员”的资料底座，不适合直接暴露给普通用户。
- Apple Liquid Glass 的核心不是到处透明，而是让控件和内容保持层级、可读性、动态材料感；需要提供降低透明/减少动效选项。

## MVP 流程

1. 创建房间：房主设定主题、可见性、评分维度和是否启用 AI 回应。
2. 添加音乐：用户输入标题/作者或分享链接。
3. 链接解析：识别 Spotify / Apple Music / 网易云 / QQ 音乐等平台，提取候选 ID 或关键词。
4. 候选搜索：并行查询多源 API，返回专辑、歌曲、艺人、封面、年份、厂牌和外链。
5. 消歧选择：用户选择正确歌曲/专辑和要呈现的封面。
6. 评论与评分：好友写短评、打分、贴标签、标记高亮曲目。
7. AI 辅助：后台根据元数据和评论生成创作背景、相似推荐、追问和“为什么你会喜欢”分析。
8. 展柜沉淀：房间可以切换展柜模式、评论模式、AI 推荐模式、资料研究模式。

## 代理分工

- 链接解析代理：展开短链，识别平台 URL 结构，抽取 song / album / playlist ID。
- 元数据代理：调用 Spotify、Apple/iTunes、MusicBrainz、Cover Art Archive、Discogs、Last.fm。
- 消歧代理：按标题、艺人、年份、ISRC、UPC、曲目长度、封面和地区版本打分。
- 乐评研究代理：抓取或检索专业乐评摘要、厂牌/制作人信息、创作背景。
- 评论陪伴代理：根据用户评论温和追问、总结共同偏好，避免替用户下结论。
- 推荐代理：生成下一批相似歌曲/专辑，并解释推荐理由和可调参数。
- 质量代理：检查 API 来源、版权合规、封面授权、链接失效、重复专辑合并。

## 技术架构

- 前端：React / Vite / PWA，移动端优先，桌面端支持多栏工作台。
- 后端：Node API 或 Edge Functions，统一 `/resolve-link`、`/search`、`/metadata/:id`、`/ai/recommend`。
- 数据库：Postgres 保存房间、成员、推荐、评论、候选选择、平台映射；向量库保存评论/标签/乐评摘要用于推荐。
- 队列：链接解析和多源检索进入后台任务，前端用实时状态展示。
- 缓存：音乐元数据按 source + external_id 缓存，封面使用代理缩略图和原图 URL 双存。
- AI：OpenAI Structured Outputs 生成严格 JSON，包括推荐理由、追问、风险标注和引用来源。

## API 策略

- Spotify Web API：搜索 track / album / artist，拿封面、曲目、外链。需要 OAuth / Client Credentials。
- Apple Music API：正式目录搜索需要开发者 token；iTunes Search API 可作为低门槛候选源。
- MusicBrainz + Cover Art Archive：开放数据库，适合发行版本、MBID 和封面归档；注意速率和 CAA 可用性。
- Discogs：适合实体发行、厂牌、版本和 credits，但需要 token，图片和内容使用要遵守条款。
- Last.fm：适合 tags、相似艺人、用户 scrobble 和社交信号。
- 网易云/QQ 音乐：优先解析分享链接中的公开字段；非官方 API 只作为适配器，必须隔离、可关闭、可替换，并提示稳定性与合规风险。

## 精致体验细节

- 候选结果必须展示封面、标题、艺人、年份、平台、置信度和“为什么匹配”。
- 同名结果先显示差异：发行年份、版本名、曲目数、封面、地区。
- 评论区支持“短评”“逐曲笔记”“制作细节”“第一次听的场景”四种入口。
- AI 回应不要抢戏：默认折叠，提供“追问我”“推荐下一批”“解释制作背景”“反思我的口味”。
- 展柜模式突出封面和好友头像，像一个可分享的音乐房间。
- 提供降低透明度、减少动效、高对比度，避免玻璃拟态影响阅读。
- 所有导入都要先经过用户确认，未经确认不进入正式档案。

## 后续增强

- 扩展 Spotify、Apple Music、MusicBrainz、Discogs、Last.fm 的深度元数据适配器。
- 对 Spotify / Apple / 网易云 / QQ 音乐链接增加更多平台 ID 回填。
- 增加 OpenAI-compatible JSON schema，生成相似推荐和评论回应。
- 扩展 Playwright 回归：权限边界、成员退出、房间列表、图片代理、无障碍键盘路径。

## 心流小屋（1.6.0 起）

目标：做成类似 Chill Pulse 的软件，在像素 Lo-fi 小屋里一边听喜欢的歌一边专注，平时也能把小屋当作桌面背景和桌宠。

第一阶段（1.6.0，已完成）：
- 像素小屋作为默认主界面，带天气、昼夜光线和小猫。
- 番茄钟、待办、统计和奖励，以及沉浸模式。
- 程序合成的环境音和离线 Lofi 电台。
- 桌宠窗口，动态桌面复用小屋。
- 本地音乐和系统正在播放两个新音源。
- 可安装的 PWA。

参考项目：meel-hd/lofi-engine（Tone.js 生成、番茄钟、Zen 模式）、btahir/next-beats（混音器）、Study Saga（经验值与连续天数）、music-assistant/server、Yyyangshenghao/simple-music。只借鉴思路，不复制代码。

第二阶段：
- 专注、待办和奖励的云端同步：作为 `api/auth.js` 的 action 加入，不新增 Vercel 函数，因为现在已有 11 个，接近免费额度上限 12 个。
- Spotify OAuth：同步歌单和收藏专辑。
- 用 Capacitor 打包 Android。
- 更多房间场景，以及可替换的桌宠素材包。
- 手机竖屏下压缩顶栏。
